# Contributing

Use issues for reproducible bugs and scoped proposals. Do not include private keys, seed phrases, signatures, environment files or exploit details; see [SECURITY.md](SECURITY.md).

Before opening a pull request:

1. Explain the behavior you are changing and the routes it touches
2. Keep the change to that behavior; avoid unrelated formatting or identity edits
3. Run `pnpm test` and `pnpm build`, and `pnpm check` with the dev server running
4. For UI changes, include desktop and phone screenshots and check keyboard use, reduced motion and horizontal overflow
5. For terminal or privacy changes, add or update tests and say what was mocked

Rules that keep users safe:

- Never broadcast a funded transaction to demonstrate a fix; the browser checks use a stand-in wallet that refuses to send
- Keep the server's call, the browser's re-encoding and the dry run in step; a buy must never open the wallet without all three
- Do not change the fixed sign-in message, the circuit files or their pinned hashes without a reviewed SDK upgrade
- Do not replace unavailable market data with invented prices; unknown values stay unknown
- Do not claim a supported chain or venue without implementing and testing its route
- `src/wordmark-path.js` is generated by `scripts/trace-wordmark.py`; regenerate it instead of editing it

A project-wide license has not been selected. Talk to the maintainer before submitting substantial code; no contributor license agreement is implied.
